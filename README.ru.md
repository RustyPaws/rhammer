# rhammer

[English](README.md) | **Русский**

> 🤖 Этот проект создан с помощью Claude AI (Anthropic), в основном как эксперимент по проверке возможностей ИИ. Он не задуман как конкурент кому-либо.

**rhammer** — редактор уровней для карт движка Source в стиле Valve Hammer, написанный на Rust с использованием [egui](https://github.com/emilk/egui). Он читает и записывает файлы `.vmf` и использует игровые конфигурации в духе Hammer (описания сущностей FGD, компиляторы), поэтому легко встраивается в привычный процесс создания карт для Source.

> Статус: нестабильно. Возможны шероховатости.

## Возможности

- **Поддержка VMF** — открытие, редактирование и сохранение карт `.vmf`; инстансы `func_instance` загружаются и отображаются во вьюпортах (разрешение путей как в VBSP, свойства инстансов и скрытые объекты поддерживаются).
- **Игровые конфигурации как в Hammer** — по образцу `GameConfig.txt` из Hammer (Options → Game configurations). Настройки хранятся в TOML-файле `rhammer.toml` и могут быть импортированы из `bin/GameConfig.txt` самого Hammer.
- **Парсер FGD** — классы сущностей, свойства, варианты выбора, spawnflags и ввод/вывод (I/O).
- **Граф I/O** — визуализация связей сущностей (входы/выходы) в виде графа.
- **Редактор углов и стрелки направления** — редактор pitch/yaw/roll с кругом для yaw и пресетами Up/Down/стороны света (в том числе для `movedir`); выделенные сущности показывают стрелку направления в 2D-видах.
- **Редактирование origin** — перетаскивание маркера origin у выделенной brush-сущности в 2D-видах; у новых brush-сущностей origin ставится в центр их brush'ей.
- **Инструменты редактирования** — Select, Block, Entity, Clip, Vertex и наложение текстур (Texture), а также Transform, Make hollow, Tie to entity, Move to world, поворот и отражение, блокировка текстур и undo/redo.
- **Док-интерфейс** — вьюпорты и панели Tools, Object, Textures и VisGroups размещены в раскладке `egui_dock`: перетаскиваемые разделители, перемещаемые панели, выбор вида кликом по подписи вьюпорта, переключатели в меню View и *Reset layout*; раскладка сохраняется.
- **2D- и 3D-вьюпорты** — раскладка на 4 вида, сетка, каркасный режим, имена сущностей, фокус на выделении / на всей карте, размеры выделения/блока в 2D-видах как в Hammer, выделенные объекты рисуются поверх; при выборе в 3D игнорируются обратные грани и охватывающие боксы сущностей.
- **Загрузка ресурсов** — игровые файлы монтируются из `SearchPaths` в `gameinfo.txt` (включая пути `|appid_<id>|`, которые используют шаблонные моды SDK `mod_tf`/`mod_hl2mp`); архивы VPK, текстуры VTF (включая прозрачные текстуры, помеченные в VMT) и модели MDL (с VVD/VTX/ANI).
  - `|appid_<id>|` определяется через библиотеки Steam: папка `steamapps` выше мода, стандартные места установки Steam, плюс все библиотеки из `libraryfolders.vdf`. Поле **Steam folder** в Options → Editor options (папка Steam, в которой лежит `steamapps`) принудительно задаёт установку Steam вместо стандартных мест.
- **Браузер текстур и просмотрщик моделей** — просмотр текстур, вращение и панорамирование (правая/средняя кнопка мыши) текстурированных моделей, воспроизведение анимаций, показ костей и attachment-точек; просмотрщик моделей также служит выбором модели для ключей `studio`.
- **Компиляция карт** — запуск `vbsp` → `vvis` → `vrad`, копирование BSP и запуск игры с живым логом компиляции (Map → Run map…).
- **Поиск, копирование/вставка, дублирование** и другие повседневные операции редактирования.

## Сборка

Понадобится актуальный стабильный [тулчейн Rust](https://rustup.rs/).

```sh
git clone <repository-url>
cd hammer
cargo run --release
```

В Linux сначала установите пакеты для разработки (те же, что используются в CI):

```sh
sudo apt-get install -y libgtk-3-dev libxkbcommon-dev libwayland-dev libx11-dev libxcb1-dev libgl1-mesa-dev
```

## Веб-версия

rhammer работает и в браузере (WebAssembly + WebGL2). Веб-сборка — это Cargo-фича `web`, десктопная — фича `local` (по умолчанию). Отличия от десктопной версии:

- **Файлы игры** читаются через [File System Access API](https://developer.mozilla.org/docs/Web/API/File_System_API): *File → Open game folder…* (или *Add game folder…* в окне конфигураций игры) и выберите папку игры, например `Portal 2`. Конфигурация игры (FGD, сущности по умолчанию, каталоги) определяется по `bin/GameConfig.txt` или `gameinfo.txt`. Ничего не загружается на сервер, файлы читаются локально.
- **Карты** открываются и сохраняются через файловые диалоги браузера, прямо на вашем диске.
- **Только Chromium** — Chrome, Edge или Opera на компьютере. В Firefox и Safari этого API нет, rhammer покажет предупреждение.
- **Браузер не открывает системные папки.** Стандартную папку Steam `C:\Program Files (x86)\Steam` выбрать нельзя, поэтому скопируйте папку игры (`steamapps/common/Portal 2`) в обычную папку, например в «Документы» или на рабочий стол, и выберите копию.
- Папки запоминаются между визитами; браузер может попросить подтвердить доступ заново (появится кнопка *Reconnect*). Настройки хранятся в локальном хранилище браузера.
- **Компиляторов нет**: запуск `vbsp`/`vvis`/`vrad` и настройки компиляции есть только в десктопной версии. Каркасный режим 3D-вида тоже только на десктопе.

Локальная сборка и запуск через [Trunk](https://trunkrs.dev/) (`cargo install trunk`, `rustup target add wasm32-unknown-unknown`):

```sh
trunk serve            # http://127.0.0.1:8080
trunk build --release  # статические файлы в dist/
```

Workflow *Web* публикует каждый пуш в `main` на GitHub Pages (включите *Settings → Pages → Source: GitHub Actions*) и прикладывает к каждому релизу статический архив `rhammer-vX.Y.Z-web.zip`. Раздавайте содержимое архива по HTTP(S) (например, `python -m http.server`); выбор папки не работает с `file://`.

## Релизы

Отправка тега вида `vX.Y.Z` запускает workflow релиза, который собирает и публикует архивы для:

- Windows (amd64, aarch64)
- macOS (aarch64)
- Linux (amd64, aarch64)
- Web (zip со статическим сайтом, см. выше)
